# 01 · 开发规范

## 1. 定位与功能范围

**功能范围不设限**，由项目所有者决定。所有者在任务中提出的功能，实现者按任务执行，不自行增删需求。

常见方向（仅举例，不是上限）：性能/帧稳定、HUD 信息、视觉调整、手感/动画、便捷操作、战斗辅助类功能等。

实现要求：
- 每个功能必须是独立模块，**默认关闭**，可随时一键关闭；关闭后行为完全恢复原版。
- 涉及发包、移动、攻击逻辑的模块，归入对应 `Category`，并在模块描述中写清其作用。
- 实现者可在汇报中提示风险（如服务器反作弊检测），但不得以此拒绝执行。

## 2. 技术栈（固定，不得更改）

## 4. 命名与代码风格

- 包名全小写；类名 `UpperCamelCase`；方法/字段 `lowerCamelCase`；常量 `UPPER_SNAKE_CASE`。
- 模块类以功能命名，不带 `Module` 后缀：`OldAnimations`、`TargetHud`。
- Mixin 类：`Mixin` + 目标类名，如 `MixinEntityRenderer`；Accessor 用 `Accessor` + 目标类名，Invoker 同理。
- Mixin 中注入方法名：`hoptimization$描述`（带前缀防冲突），如 `hoptimization$onRenderHand`。Mixin 新增字段同理加 `hoptimization$` 前缀并 `@Unique`。
- 缩进 4 空格，UTF-8，LF/CRLF 跟随 `.gitattributes`，单行 ≤ 120 字符。
- 大括号不省略；`if` 单行也加括号。
- 公共 API 写简短 Javadoc（一句话说明意图），**注释写"为什么"而不是"做了什么"**。
- 禁止 `System.out`，统一 `HoptimizationMod.LOGGER`。
- 禁止吞异常；`catch` 至少 `LOGGER.error(..., e)`。

## 5. Mixin 规范

1. 优先级：**Forge 事件 > `@Inject` > `@Redirect`/`@ModifyVariable`/`@ModifyArg` > 其它**。能用 Forge 事件解决就不写 Mixin。
2. **禁止 `@Overwrite`**。
3. `@Redirect` 会与其它 mod 冲突，使用前在 PR/汇报中说明原因。
4. 每个注入点必须在注释里写明：目标方法、目的、是否受模块开关控制。
5. Mixin 里**只做转发**：判断开关 → 调用 `modules/` 或 `core/` 中的逻辑。不在 Mixin 中写业务。
6. 使用 MCP 名（开发环境），refmap 自动生成；Access Transformer 使用 SRG 名。
7. 访问私有字段优先 `@Accessor`，其次 AT，**禁止运行时反射**。
8. 每新增一个 Mixin，必须 `runClient` 启动一次确认无 `InvalidInjectionException`。

## 6. 模块系统约定

```java
public abstract class Module {
    String id;            // 稳定的配置键，小写下划线，如 "old_animations"，发布后不得改
    String nameKey;       // 语言键，如 "module.hoptimization.old_animations.name"
    String descKey;       // 语言键，一句话描述（≤ 40 中文字符）
    Category category;
    boolean enabled;
    boolean toggleable;        // 默认 true；false 表示仅配置控制型模块（如 clickgui），不可开启
    boolean requiresCheatMode; // 默认 false；true 表示需开启 CheatMode 才可用
    int keybind;               // LWJGL Keyboard 码，0 = 未绑定
    List<Setting<?>> settings;

    public boolean isAvailable() { ... } // !requiresCheatMode || HoptimizationMod.isCheatModeEnabled()
    protected void onEnable() {}
    protected void onDisable() {}
}
```

- 模块启用时向 `MinecraftForge.EVENT_BUS` 注册自身，禁用时注销；**禁止在禁用状态下还跑逻辑**。
- `toggleable = false` 或 `!isAvailable()`（未开启 `CheatMode` 时的作弊门禁模块）禁止通过 `setEnabled(true)`、`toggle()` 或快捷键开启；关闭 `CheatMode`（`cheat_mode`）时必须自动禁用全部需要作弊模式的模块。
- `Category` 固定为：`COMBAT 战斗`、`MOVEMENT 移动`、`VISUAL 视觉`、`UI 界面`、`PERFORMANCE 性能`、`MISC 杂项`（旧配置中的 `"hud"` 在反序列化时兼容映射至 `UI`）。新增分类需进"待决策"。
- Setting 类型固定五种：`BooleanSetting`、`NumberSetting(min,max,step)`、`ModeSetting(String...)`、`ColorSetting(ARGB, allowAlpha)`、`KeybindSetting`。支持 `visibleWhen(Supplier<Boolean>)` 做依赖显隐。
- 所有展示文本走 `I18n.format(key)`，**禁止硬编码中文/英文到 UI**。必须同时补 `en_US.lang` 和 `zh_CN.lang`。

## 7. 配置

- 路径：`.minecraft/config/hoptimization/`
  - `profiles/<name>.json`：模块开关、按键、设置值；加载配置档时必须**优先加载 `cheat_mode`**，使依赖作弊模式的模块可按当前状态正确恢复或拦截
  - `ui.json`：主题强调色、通用 GUI 缩放（`uiScaleMultiplier`）、ClickGUI 独立缩放（`clickGuiScale`，范围 `0.75–2.0`，默认 `1.25`）、打开按键、上次打开的分类、HUD 布局
- 读写使用 Gson，`setPrettyPrinting()`。
- 读取容错：未知键忽略、缺失键用默认值、类型错误回退默认并 `LOGGER.warn`。**配置损坏不得导致游戏崩溃**。
- 写入：先写 `*.tmp` 再原子替换；在 GUI 关闭、游戏退出时保存，不要每帧/每次拖动滑条都写盘（滑条松手后防抖 500ms 写入）。

## 8. 性能规范（战斗优化 mod，性能是底线）

- 渲染与 Tick 热路径：**零分配**。复用对象、预计算、缓存字符串宽度。
- 禁止在热路径用 Stream API、自动装箱、字符串拼接、`String.format`。
- 字体：字形图集一次性生成并缓存；字符串宽度做 LRU 缓存。
- OpenGL 状态：谁改谁还原（`GlStateManager` 优先，必要时 `GL11.glPushAttrib`）。渲染结束必须恢复 `enableTexture2D`、`disableBlend` 前的状态，避免污染原版渲染。
- Shader 编译失败必须**自动回退**到固定管线实现，并只 warn 一次。
- 动画基于真实时间（`System.nanoTime()` 增量），**不依赖帧率**。
- 目标：ClickGUI 打开时额外开销 < 0.5ms/帧（中端机）；HUD 全开 < 0.3ms/帧。

## 9. 线程

- 所有游戏/渲染相关操作只在客户端主线程。
- 配置文件写盘可放后台单线程执行器，但数据快照必须在主线程生成。

## 10. 兼容性

- 必须与 OptiFine（1.8.9 HD U M5/L5）共存不崩溃。涉及 `EntityRenderer`、`RenderGlobal`、`ItemRenderer` 的 Mixin 尤其注意，必要时在 `shouldApplyMixin` 中按条件跳过。
- 不依赖 GUI Scale：自研 UI 使用自己的缩放体系（见 `02_美术规范.md §8`）。

## 11. Git 与版本管理

**强制遵守 `04_版本管理规范.md`**。核心：每次更新必须提交并推送 GitHub，且能一条命令退回上一个版本。

## 13. 完成定义（DoD）

一个任务只有同时满足以下全部条件才算完成：
1. `.\gradlew.bat build` 通过，无新增警告级 Mixin 报错；
2. `runClient` 实测功能可用、关闭模块后行为完全恢复原版；
3. 符合 `02_美术规范.md`（UI 类任务）；
4. 中英文语言键齐全；
5. `PROGRESS.md` 已更新；
6. 已按 `04_版本管理规范.md` 提交、打标签并推送到 GitHub。
