# 04 · 版本管理规范（Git + GitHub）

> 目标：**任何一次更新都能安全退回上一个版本**，且所有版本都在 GitHub 上有备份。

## 1. 首次初始化（仅在仓库尚未建立时执行一次）

```powershell
cd D:\AIprojects\Hoptimization
git init -b main
git config user.name  "<所有者提供>"
git config user.email "<所有者提供>"
git remote add origin <所有者提供的 GitHub 仓库地址>
git add .
git commit -m "chore: 初始化项目与开发规范"
git tag -a v0.1.0-init -m "初始版本"
git push -u origin main --tags
```

- 用户名、邮箱、仓库地址**必须由所有者提供**，不得编造。缺失时停止推送步骤，在 `PROGRESS.md`「待决策」中写明，本地提交照常进行。
- 推送认证使用所有者本机已配置的凭据（Git Credential Manager / SSH key）。**不得**把 Token 写进仓库文件、远程 URL 或文档。
- 若 `.gitignore` 缺失下列条目，先补上：`build/`、`run/`、`.gradle/`、`.idea/`、`.vscode/`、`*.iml`、`*.log`、`out/`。

## 2. 分支模型

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 永远可编译、可运行的稳定版本 | 只接受合并，不直接在上面写代码 |
| `feat/<简述>` | 一个任务一个分支，如 `feat/clickgui-sidebar` | 从最新 `main` 切出 |
| `fix/<简述>` | 修复 | 同上 |

## 3. 每次更新的标准流程（强制）

```powershell
# 1. 开工：确认干净并同步
git status                      # 必须干净；不干净先询问所有者，不得擅自丢弃
git checkout main
git pull --ff-only origin main
git checkout -b feat/<简述>

# 2. 开发中：小步提交（每个可编译的单元一次）
git add <具体文件>             # 不要无脑 git add -A，检查 git status
git commit -m "ui(clickgui): 实现侧边栏分类切换动画"

# 3. 收工：验证 → 合并 → 打标签 → 推送
.\gradlew.bat build             # 必须通过，否则不得合并
git checkout main
git merge --no-ff feat/<简述> -m "merge: <任务标题>"
git tag -a v<版本号> -m "<任务标题>"
git push origin main --tags
git push origin feat/<简述>     # 分支也推送，保留历史
```

- `--no-ff` 保证每次更新在 `main` 上是**一个独立合并节点**，回退时一步到位。
- **每次合并到 `main` 都必须打标签**，标签即"版本快照"。

## 4. 提交信息格式

`<type>(<scope>): <中文简述>`

- type：`feat` 新功能 · `fix` 修复 · `perf` 性能 · `refactor` 重构 · `ui` 界面/美术 · `style` 仅格式 · `docs` 文档 · `chore` 构建/杂项
- 一个提交只做一件事；正文（可选）写"为什么改"。

## 5. 版本号

语义化版本 `MAJOR.MINOR.PATCH`，与 `gradle.properties` 的 `version` 以及 `HoptimizationMod.VERSION` **三处同步**：
- 新功能/新模块 → MINOR +1（`0.1.0 → 0.2.0`）
- 修复/微调 → PATCH +1（`0.2.0 → 0.2.1`）
- 1.0.0 之前不升 MAJOR
- 仅文档变更可不升版本，标签用 `v<当前版本>-docs.<n>`

> 注：修改 `gradle.properties` 的 `version` 字段属于版本管理流程，不违反"不得改构建文件"红线；其它字段仍禁止改动。

## 6. 回退方法（写给所有者，也写给 AI）

| 场景 | 命令 | 说明 |
|---|---|---|
| 查看所有版本 | `git tag -n` / `git log --oneline --graph` | |
| 临时试用旧版本 | `git checkout v0.2.0` | 只读查看，回来用 `git checkout main` |
| **撤销最近一次更新（推荐）** | `git revert -m 1 <合并提交>` 然后 `git push` | 生成新的反向提交，历史不丢，安全 |
| 撤销某个普通提交 | `git revert <提交>` | 同上 |
| 从旧版本重新开始 | `git checkout -b fix/rollback v0.2.0` | 在新分支上继续 |

- **禁止** `git push --force`、`git reset --hard` 已推送的提交、删除远程标签——除非所有者明确书面要求。
- 回退本身也是一次更新：同样要 build、打标签（PATCH +1）、推送、记 `PROGRESS.md`。

## 7. 安全红线

- 不得提交：构建产物、`run/` 目录（含存档与账号缓存）、日志、任何 Token/密码/账号信息。
- 提交前执行 `git status` 与 `git diff --staged` 自查。
- 推送失败（网络/认证）时：**本地提交与标签保留**，在 `PROGRESS.md` 记录"未推送"，不得为了推送而改远程地址或认证方式。

## 8. PROGRESS 记录中必须包含

```
- **Git**：分支 feat/xxx → main，标签 v0.2.0，推送 ✅/❌
- **回退到上一版本**：git revert -m 1 <合并提交短哈希>
```
